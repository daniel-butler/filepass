# filepass Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build filepass, a single Rust binary that lets agents hand each other files over plain HTTP: upload with `curl -T` and a bearer token, download with an unguessable expiring URL.

**Architecture:** A library crate (`src/lib.rs`) holds every module; `src/main.rs` is a thin CLI. axum serves the HTTP API from shared `AppState`. Files live on disk as `files/{id}` plus `files/{id}.json`, mirrored by an in-memory index behind a `std::sync::Mutex`. Every counter is an RAII guard. Downloads stream from a spawned producer task; upload commits run in a spawned task so a disconnect cannot cancel them.

**Tech Stack:** Rust 2021 (rustc 1.94 available), axum 0.8, tokio 1, tokio-util 0.7, futures-util 0.3, sha2 0.10, hex 0.4, base64 0.22, rand 0.9, serde 1, serde_json 1, toml 0.9, humantime 2, percent-encoding 2, tracing 0.1, tracing-subscriber 0.3 (`json`, `env-filter`), clap 4 (`derive`), ipnet 2, nix 0.31 (`fs`), thiserror 2. Dev: reqwest 0.12 (`stream`), tempfile 3, tokio (`test-util` not used — real time with short config values).

**Spec:** `docs/superpowers/specs/2026-10-07-filepass-design.md`. Every task implements the spec sections it names; read them before starting. Where this plan and the spec disagree, the spec wins — report the conflict.

## Global Constraints

- License MIT; `Cargo.toml` `license = "MIT"`, `repository = "https://github.com/daniel-butler/filepass"`.
- No `tower-http`. No `Path`/`RawPathParams` extractors anywhere. No extractor may reject a request (spec: "Handlers own every response").
- Never log a full file id (log `&id[..8]`), a token, a token hash, or a request URI.
- The index lock is `std::sync::Mutex` and is never held across `.await`.
- All defaults exactly as the spec's Configuration block: `max_file_size` 2GiB, `default_ttl` 30m, `max_ttl` 24h, `tombstone_ttl` 48h, `max_tombstones` 200000, `upload_idle_timeout` 60s, `max_upload_duration` 1h, `download_idle_timeout` 60s, `max_download_duration` 2h, `shutdown_grace` 30s, `total_quota` 50GiB, `agent_quota` 10GiB, `max_files` 1000, `min_free_space` 5GiB, `min_free_inodes` 10000, `upload_rate` 60, `max_concurrent_uploads` 32, `max_uploads_per_agent` 8, `max_concurrent_downloads` 64, `max_downloads_per_ip` 8, `trusted_proxies` `["127.0.0.1", "::1"]`, `log_format` `"text"`. `listen`, `public_url`, `data_dir` are required.
- Ids: 32 lowercase hex chars from 16 random bytes. Tokens: `fp_` + base64url-no-pad of 32 random bytes.
- Download chunk size 256 KiB; producer channel capacity 4.
- Every `429`/`503` carries `Retry-After`.
- Metric names, labels, and `result`/`reason` values exactly as the spec's Telemetry section.
- Run `cargo fmt` and `cargo clippy --all-targets -- -D warnings` before every commit; both must be clean.
- Commit messages: imperative, no model names.

## Review Focus

1. **Authorization header variants** — `bearer x` (lowercase scheme), `Bearer  x` (two spaces), `Token x`, an empty value, a non-UTF-8 header. Expect `401` every time, never a panic or `400`. Test in Task 2.
2. **Exact boundaries** — an upload of exactly `max_file_size` bytes succeeds; one byte more is `413`; an upload that brings an agent to exactly `agent_quota` succeeds. Test in Task 8.
3. **Expiry while downloading** — a file that expires (test clock advanced, sweep run) mid-download still completes with the full body. Test in Task 9.
4. **Malformed config hashes** — `token_sha256` in uppercase hex is accepted (normalised); wrong length or non-hex is a config error naming the agent, never a panic. Test in Task 1.
5. **Disk error at commit** — a `.json` write failure after the blob rename answers `500`, unlinks the blob, and leaves every counter at zero. Test in Task 8.

Checks `max_file_size` (`TooLarge`), then `max_files` (live + reserving), `agent_quota`, `total_quota`, free space and inodes per the spec formula (`Insufficient`). Reserves one file slot plus `declared.unwrap_or(0)` bytes.
  - `Reservation::grow(&mut self, written_total: u64) -> Result<(), ReserveError>` — for streamed uploads: when `written_total` exceeds reserved bytes, extend in 1 MiB steps with full re-check (`max_file_size` → `TooLarge`). For declared uploads, exceeding the declared length → `TooLarge`.

On `.json` failure: unlink blob, return `Err` (reservation drops).
